# 总结

## 思考路径

模型：右端点排序 + last + BIT
排序维度：询问 r 升序
维护结构：BIT 维护每种颜色最后一次出现的位置
识别信号：静态区间 distinct
误判：想直接维护 [l,r] 颜色集合

## 什么时候可以用离线

1. 询问之间有没有依赖？
如果每个询问只是问初始数据的某个性质，而且答案不会影响后面的操作，那就可以考虑离线。

2. 能不能把某个限制变成“从小到大加入”？
| 限制        | 排序对象   | 维护结构     |
| --------- | ------ | -------- |
| 区间右端点 r   | 按 r 升序 | BIT      |
| 值 > k     | 按 k 降序 | BIT      |
| 边权 <= q   | 按边权升序  | DSU      |
| 坐标 x <= X | 按 x 升序 | BIT 统计 y |
| 前 k 大     | 按值降序加入 | BIT 找位置  |

3. 能不能“排序一维，数据结构维护另一维”？
比如二维条件：
x <= X 且 y <= Y
l 更大且 r 更小
a[i] > k 且 i 在 [l,r]

4. 能不能先把询问本身“转化成贡献” 
这是容易混淆的题目, 转化成贡献就不需要离线处理

## 总结

1. 询问互不影响，且不要求在线输出，优先考虑重排询问。

2. 有 <=x、>=x、右端点 r、边权 w、坐标 x、前 k 大，优先考虑排序后单调加入。

3. 离线维护的通常不是原问题本身，而是“当前已经激活的元素集合”。

4. 二维限制优先想：排序一维，BIT 维护另一维。

5. 区间 distinct 不要直接维护集合，优先想 last 出现位置。

6. 树上路径最大边权不超过 q，不要先想 LCA，先想边权排序 + DSU。

7. 如果最终只问总贡献/最终结果，不要维护每次操作，先统计每个位置/操作被贡献几次。

8. 前 k 大 + 原序第 pos 个：值排序决定集合，BIT 维护位置，kth 找答案。

9. 同值元素属于主目标平局，优先选对副目标更有利的代表。
